DOOM 포팅 / RESEARCH NOTE

게임은 카메라에서, 화면은 브라우저로

MIPS 위에서 실행되는 DOOM과 브라우저 사이를 WebSocket으로 연결한 화면·입력 구조.

2026.10.25Embediz
01

실행 위치와 표시 위치를 나누다

DOOM은 PC 브라우저가 아니라 JOOAN 홈캠의 CPU에서 실행됩니다. 기기에서 생성한 화면 데이터를 WebSocket으로 전달하고, 브라우저에서는 JavaScript와 Canvas로 표시합니다. 카메라의 원래 센서 영상 스트림과는 별도의 출력 경로입니다.

02

화면을 전달하는 경로

doomgeneric의 DG_DrawFrame에서 화면 버퍼를 확보하고, Mongoose를 통해 바이너리 메시지로 전송합니다. 브라우저는 전달받은 320×200 픽셀 데이터를 Canvas에 그립니다. 초기 BMP 반복 전송 방식에서 최종 WebSocket 방식으로 구성을 변경했습니다.

03

입력은 반대 방향으로

브라우저에서 키의 눌림과 해제를 구분해 같은 WebSocket 연결로 전달합니다. 기기는 수신한 이벤트를 입력 큐에 저장하고, DG_GetKey를 통해 DOOM에 반환합니다. 브라우저가 포커스를 잃거나 연결이 종료될 때도 입력 상태를 정리하도록 구현했습니다.

04

확인한 결과와 남은 한계

실기기 최종 시연에서 웹 Reset 버튼을 통한 실행, 게임 페이지 이동, 시작 화면과 게임 진행 중의 장면 갱신을 확인했습니다. 최종 WebSocket 구성의 정확한 fps와 장시간 실행 안정성은 검증하지 않았습니다.
